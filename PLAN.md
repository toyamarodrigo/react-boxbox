# react-boxbox — Implementation Plan

> **react-boxbox** is the project. **boxbox** is the brand.
> Animated, F1-broadcast-inspired React components, distributed as a shadcn registry (`@boxbox/*`).

Decisions were settled in the design session on 2026-09-20. This file is the work order. Each step ends in a commit that passes `typecheck`, `lint`, `format:check`, and `test`.

## Phase 0 — Bootstrap (1 session)

**Goal:** empty app deploys to Vercel, CI green.

1. **Scaffold** TanStack Start with bun. Configure `tanstackStart({ spa: { enabled: true, prerender: { enabled: true } } })` and `nitro()` from `nitro/vite`. Confirm `bun run build` produces a static shell.
2. **Tailwind v4 + shadcn init** (`new-york`, CSS variables, base color neutral). Add `components.json` with `"registries": { "@boxbox": "https://react-boxbox.vercel.app/r/{name}.json" }` so the site can dogfood its own registry later.
3. **Tooling**: `.oxlintrc.json` (react, jsx-a11y, react-hooks native rules), `.oxfmtrc.json`, `vitest.config.ts` with jsdom + Testing Library, strict `tsconfig`. Scripts: `dev`, `build`, `typecheck`, `lint`, `format`, `format:check`, `test`, `registry:build`.
4. **GitHub**: `gh repo create react-boxbox --private`, push. `ci.yml`: bun install → typecheck → lint → format:check → test → build, on push and PR.
5. **Vercel**: link project, first deploy. (User runs `vercel login` if needed.)

**Done when:** `react-boxbox.vercel.app` serves a placeholder page and CI is green.

- Imports inside registry files: `@/registry/boxbox/lib/types`, `@/registry/boxbox/ui/<other>`, `@/lib/utils` for `cn`. Nothing from `src/`.

## Phase 4b — Motion pass (1–2 sessions)

**Goal:** every state change a viewer cares about is visible as motion, and nothing else moves. Reviewed against Emil Kowalski's design-engineering rules (`/emil-design-eng`), adapted to broadcast graphics: these components are watched, not operated, so motion *is* the state indication. Keep it crisp: UI durations ≤ 300ms, strong ease-out on enters, ease-in-out or a bounce-less spring on movement, no bounce, `transform` / `opacity` / `clipPath` only.

**Ground rules for this phase**

- Motion tokens live in one `registry:lib` item, `boxbox-motion` (`registry/boxbox/lib/motion.ts`), added to every component's `registryDependencies`: `EASE_OUT = [0.23, 1, 0.32, 1]`, `EASE_IN_OUT = [0.77, 0, 0.175, 1]`, `DURATION = { tick: 0.15, fast: 0.2, base: 0.3, slow: 0.45 }`, `SPRING_ROW = { type: 'spring', duration: 0.45, bounce: 0 }`. No component defines its own curve after this step.
- Anything that animates while the simulator ticks (Timing Tower, Sector Times) uses the full `transform: 'translateY(...)'` string, `opacity`, or `clipPath`, not the `x` / `y` / `scale` shorthands. Motion only hardware-accelerates the full string (confirmed in the Motion performance docs); shorthands run on the main thread and drop frames when 20 rows re-render.
- Exit is always faster than enter. Enter ≈ `base`, exit ≈ `fast`.
- Elements never appear from `scale(0)`; start at `scale(0.95)` or `opacity: 0` plus a few pixels of travel.
- Reduced motion: `MotionConfig reducedMotion="user"` is already in `src/routes/__root.tsx`. It removes transform and layout motion but keeps opacity and colour, so every change below must still read with colour alone. Document the wrapper in `/docs/installation` so registry consumers get the same behaviour.
- Tests assert structure and data attributes, never timing. Anything timer-driven (demo hooks) is unit-tested with fake timers.

**Motion decision table**

| Component | Trigger | Motion | Why |
|---|---|---|---|
| Timing Tower | Row changes position | `layout="position"` on `motion.li` with `SPRING_ROW`; `<ol>` becomes `relative` and wraps rows in `LayoutGroup` + `AnimatePresence mode="popLayout" initial={false}` | Size never changes, so `position` is cheaper than full `layout`. Presence lets rows entering or leaving via `maxRows` fade instead of popping. |
| Timing Tower | Position gained / lost | **Fix the dead flash**: mount the position cell with `initial={{ backgroundColor: flash }}` → `animate` to transparent over `DURATION.slow`, ease-out. Green on gain, red on loss. Position digit rolls: old digit exits up and new enters from below on a gain, the reverse on a loss (`AnimatePresence mode="popLayout"`, `DURATION.fast`). ▲/▼ fades in with the flash. | Today the cell remounts with `initial={false}` and a keyframe array, so Motion paints the final keyframe and no flash ever plays. Direction of the digit roll encodes the meaning. |
| Timing Tower | Gap / interval tick | Keep the value swap but shorten to `DURATION.tick`, travel 3px, full `transform` string | Fires on every row every tick; this is the "tens of times" bucket, so reduce rather than embellish. |
| Timing Tower | PIT / DRS tag appears or disappears | `AnimatePresence`, opacity + 4px slide from the left, enter `fast`, exit `tick` | Prevents tags from popping in a moving row. |
| Timing Tower | Driver takes fastest lap | One-shot purple flash on the value cell, same mechanism as the position flash | State indication. Only when `isFastestLap` flips to true, not on every render. |
| Sector Times | Several sectors update in one render | Stagger bar fills 60ms apart in sector order; sector time text fades and slides 4px with its bar | "Elements all appear at once" is the review-checklist failure. Still short enough to feel like one event. |
| Sector Times | Sector resets to unset | Bar exits with opacity over `DURATION.tick` instead of remounting instantly | Avoids a hard cut when a new lap starts. |
| Sector Times | Lap completes as session fastest | Lap value flashes `--sector-fastest` once, count-up unchanged (600ms ease-out) | Same pattern as the tower's fastest-lap flash for cohesion. |
| Driver Name Plate | Status added / removed / changed | `AnimatePresence mode="popLayout"` on the status part, `clipPath` wipe in the plate's `align` direction, `DURATION.fast`; `layout` on the plate root so width changes animate | Today the status pops and the plate jumps in width. |
| Driver Name Plate | Position changes | Digit roll shared with the tower (extract `RollingNumber` into `boxbox-motion` or a small shared UI part) | One implementation, two consumers. |
| Tyre Badge | Age ticks | Optional: number slides 3px with opacity, `DURATION.tick` | Cheap, cohesive with the tower value. Skip if it looks busy inside the tower. |
| Replay Bumper | Panel wipe / slide | Switch panel and label from `x` to the full `transform: 'translateX(...)'` string | The content swap at the midpoint runs on the main thread; the wipe must not drop frames. Keep `easeIn` on the exit: the panel is accelerating off-screen, not settling on it. |
| Start Lights | Lights out | **No change.** Lights go dark instantly | The instant cut is the event. Animating it would delay the only moment that matters. The 150ms light-on and the aborted pulse stay. |
| All | Variant, layout, size, align changes | No animation | Configuration, not state. |

**Steps**

22. **Motion tokens**: add `boxbox-motion` to `registry.json`, migrate every component to it, rebuild `public/r/`, verify the item installs into the scratch app. Add the `MotionConfig` note to `/docs/installation`.
23. **Timing Tower**: implement the five tower rows of the table plus the `LayoutGroup` / `AnimatePresence` wrapper. Add a shared `RollingNumber` part. Extend tests for the presence wrapper (`maxRows` shrink still renders the right rows) and the fastest-lap flag. Demo: unchanged except that `speed` also drives the row spring duration cap (never longer than half a tick).
24. **Sector Times**: stagger, text fade, reset exit, fastest-lap flash. Demo: add a `useProgressiveLap(sectors, lapTime, intervalMs)` hook in `src/content/sector-times/` that reveals S1 at `0`, S2 at `interval / 3`, S3 plus the lap time at `2 · interval / 3`, and resets to `unset` when the next lap arrives. The component stays pure; the demo owns the pacing. Fake-timer tests for the hook.
25. **Driver Name Plate, Tyre Badge, Replay Bumper**: the remaining table rows. Small, one commit each.
26. **Review**: slow-motion pass at 0.25× in the DevTools Animations panel for the tower and the sectors (two states overlapping? origin correct? opacity and transform in sync?). Reduced-motion pass with the OS setting on: every state change in the table must still be readable by colour. Visual verification through `codex-computer-use`. Revisit with fresh eyes the next day before closing the phase.

**Done when:** an overtake in the tower reads as one event (row slides, digit rolls, cell flashes, arrow appears), sectors complete one by one in the live demo, and no component defines its own easing.

## Phase 11 — Gap or interval in the tower (grilled 2026-09-22)

**Goal:** let the viewer choose what the Timing Tower's value column measures on the Replay page — the **gap** to the leader, or the **interval** to the car one place ahead. One delivery.

Most of this already exists. `TimingTower` has taken a `mode` prop with `'leader' | 'interval' | 'lapTime' | 'results'` since Phase 3, and `replayLiveRows` has filled `TimingRow.interval` since Phase 8, measured the same way as `gapToLeader` (how long ago the car ahead passed the point this car is at now). The page simply never offered the choice: `src/routes/replay.tsx` hard-codes `mode={replay.finished ? 'results' : 'leader'}`. The phase is a control, a search param, a rename, and two corrections to `rowValue`.

**Glossary (written into `CONTEXT.md` during the session)**

**Gap** is how far a car is behind *the leader*. **Interval** is how far it is behind *the car one place ahead*. Each lists the other under _Avoid_. The two words are not interchangeable anywhere in this project from now on: not in code, not in copy, not in commit messages.

**Decisions**

| Area | Decision |
|---|---|
| Scope | **Page only.** The tower is a controlled component: whoever mounts it decides the mode. A mode button *inside* the registry item would force internal state and a placement decision on every consumer, for a choice only this page makes. |
| Which modes | **Two: Gap and Interval.** `lapTime` stays in the type and in the docs playground, but the page does not offer it: the expanded panel of the followed car already shows the last lap and its three sectors (`FollowedFigures`), an inch below. |
| Rename | `GapMode` → **`ValueMode`**, no deprecated alias. Once "gap" means *to the leader only*, a type called `GapMode` with an `'interval'` member contradicts the glossary. The rest of the code already calls this column the value column (`TimingTowerValue`, `rowValue`, `VALUE_LABELS`). Done now because it is as cheap as it will ever be: the repo is private, `v1.0.0` is untagged, and nobody has `boxbox-types` installed. The `showDrs` alias exists because *that* name shipped; this one has not. |
| Placement | In the tower column, in the row that already holds `LapCounter` and `RaceClock`. The top `Controls` bar governs the *time* of the replay; this governs *what one column measures*, and on a wide screen that bar is far from the tower. |
| Shape | **Two buttons in a `fieldset`** with `aria-pressed`, the idiom of the replay-speed picker and `RacePicker`. Labels `Gap` and `Interval` — the glossary words, matching the tower's existing spoken labels "Gap to leader" and "Interval". `aria-label="Timing column"`, no visible legend. No `Select`: this page re-renders ten times a second and is no place for a popover that re-measures itself on every tick (the reason `RacePicker` is a button row). |
| State | **In the URL: `?value=interval`.** Same class of thing as `?driver=VER` — a view of the race, not a step in it — so it navigates with `replace: true` and `resetScroll: false`, and a shared link shows what the sender sees. The default `leader` never appears in the URL. An unknown value falls back to `leader` silently, which needs `.catch()` on the field: `validateSearch` runs `searchSchema.parse`, so a bare `z.enum` would turn `?value=foo` into a route error. |
| Changing race | **The mode survives it.** `RacePicker` navigates with a whole new search and drops `driver` on purpose, because the followed driver belongs to *that* race. The column mode is a viewer preference that means the same thing in any race; losing it on every click would be a punishment with no reason behind it. |
| Race over | The control **disappears** once the race is finished and the column becomes `results` with its points. It has nothing left to switch. A permanently disabled control asks the eye to read it every time and gives it nothing — `Podium`, which only appears at the end, is the precedent. |
| Lapped car, interval mode | **Show the real interval.** `rowValue` returns the fixed `'+1 LAP'` for a lapped car in *both* modes today, which hides the one thing interval mode exists to say — the car ahead is often on the same lap and a second away. `'+1 LAP'` stays in gap mode only. |
| Lapped car, colour | **Keep the amber `status-lapped` tone in interval mode.** Once the number is an ordinary interval, the tone is the only thing left on the row saying the car is a lap down. Dropping it would delete information, not remove noise. |
| Motion | **Nothing new.** `TimingTowerValue` is keyed on its text, so all ~20 rows already cross-fade with their 3 px rise when the mode flips — the same animation a normal tick plays, and a sweep down the column reads as "this column no longer measures the same thing". A 20-row stagger would take longer than the eye allows a button press, and a button that answers late feels broken. |
| Keyboard | **No shortcut.** The page already has a slider, focusable buttons and a global `Esc` listener; another global key, for a two-button control that is in plain sight, buys less than it risks. |

**Also fixed here: `+1 LAP` lies when it is two.** In gap mode `rowValue` returns the constant `'+1 LAP'` for any lapped car, ignoring how many laps down it is, while `resultValue` reads `lapsBehind` properly once the race ends. `replayLiveRows` already fills `lapsBehind` on every live row, so today a car two laps down reads `+1 LAP` while it runs and `+2 LAPS` when it stops — from the same data. Two lines in the function this phase already rewrites; it is a correction, not part of the switch.

**Work**

1. `registry/boxbox/lib/types.ts`: `GapMode` → `ValueMode`. Update `registry/boxbox/ui/timing-tower.tsx` and `src/content/timing-tower/use-results-presentation.ts`; rebuild the registry JSON.
2. `registry/boxbox/ui/timing-tower.tsx` — `rowValue`: `'+1 LAP'` becomes `+N LAPS` from `lapsBehind` (the `resultValue` spelling), and applies in gap mode only. Tests for a lapped car in each mode.
3. `src/routes/replay.tsx` — `value` search param with `.catch()`, the two-button control in the `Stage` header row, `mode` passed through, control hidden when `replay.finished`.
4. Route tests: default is gap, the button switches the column, `?value=interval` is honoured, `?value=foo` falls back without throwing, the mode survives a race change and the followed driver does not.
5. `/react-doctor` on the diff, then one commit that passes `typecheck`, `lint`, `format:check` and `test`.

## Known issues

- **Vercel deep-link 404.** With SPA mode on Vercel, a route that was not prerendered returns Vercel's static 404 instead of `_shell.html`. Mitigation: every docs route is prerendered at build time via `crawlLinks`, so only unknown URLs 404. vercel/vercel#17627 was closed on 2026-09-17: the reporter's fix was setting the project framework preset to `tanstack-start` instead of `nitro` (with `@tanstack/router-plugin` as a direct dependency for detection). **Step 36 result (2026-09-21):** the project preset is now `tanstack-start` (changed with `vercel project update`, owner's OK). A preview deploy of a clean HEAD built fine on the new preset. Measured with `vercel curl` (preview deployments sit behind Vercel Authentication, so WebFetch only sees the SSO redirect): an unknown route returns **HTTP 404 with the app shell HTML** on the preview *and* on production, so the client router renders its own not-found page in both. The "static 404 page" symptom does not reproduce in SPA mode with either preset; the closed issue was about SSR. Decision: **stay on SPA + prerender**, keep the `tanstack-start` preset (Vercel's documented setting), and treat SSR as unblocked but unneeded until a route needs server-side data. `vercel curl` auto-generated a deployment-protection bypass token on the project; remove it in the dashboard if unwanted.
- **Vercel Git integration not connected.** `vercel git connect` fails from a git worktree and the Vercel GitHub App has no access to the private repo yet. Production deploys currently run from the CLI (`vercel deploy --prod`). Connect it from the Vercel dashboard (Project → Settings → Git) to get deploys on push.
- **Flaky route tests — fixed 2026-09-22.** In a full `bun run test` run, route tests failed at roughly one run in five and passed alone. Caught in a repeat loop and found to be two separate causes, both in the tests rather than the product. (1) **Testing Library's one-second default wait** was not enough for this suite's heaviest work: a route test builds a router, resolves two fetches, mounts the `React.lazy` gap chart and runs a 100 ms clock while forty jsdom environments compete for the CPU — the wait for the chart timed out at 2.3 s. `src/test/setup.ts` now calls `configure({ asyncUtilTimeout: 5000 })`; the limit exists to stop a hanging test, not to measure speed. The lazy chart was introduced by the Phase 8 Recharts follow-up, so this flake was self-inflicted. (2) **"does not reset the scroll to follow"** failed with `expected "bound " to not be called at all, but actually been called 1 times`: the router restores the scroll for the *first* navigation too, in a frame of its own, and on a loaded machine that frame landed after the test had cleared the spy, so the page's own arrival was read as the follow having scrolled. The test now awaits a `settleFrames()` helper before clearing. **Evidence:** twelve consecutive full runs clean after the fix, against failures in runs 1 and 7 of an eight-run loop before it. The `-index.test.tsx` "plays the newest curated race" failure was seen once before either fix and not since, across twenty runs; it was most likely the same timeout class as (1), but that is inference, not a captured failure.
