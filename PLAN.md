# react-boxbox — Implementation Plan

> **react-boxbox** is the project. **boxbox** is the brand.
> Animated, F1-broadcast-inspired React components, distributed as a shadcn registry (`@boxbox/*`).

Decisions were settled in the design session on 2026-09-20. This file is the work order. Each step ends in a commit that passes `typecheck`, `lint`, `format:check`, and `test`.

---

## Fixed decisions (do not reopen)

| Area | Decision |
|---|---|
| Names | Repo / package / Vercel: `react-boxbox`. Brand / namespace / registry name: `boxbox`. |
| Stack | React 19, TypeScript strict, Tailwind v4, shadcn CLI 4.x (`new-york`, OKLCH, `data-slot`, no `forwardRef`). |
| App | TanStack Start, **SPA mode + prerender** of all routes. Nitro Vite plugin for Vercel. SSR later. |
| Animation | `motion` (`motion/react`) only. `MotionConfig reducedMotion="user"`. |
| Tooling | bun, oxlint (react + jsx-a11y plugins), oxfmt, Vitest + Testing Library, GitHub Actions. No git hooks, no Storybook. |
| Zod 4 | Site only: playground control schemas and dataset validation. Never inside registry components. |
| Distribution | shadcn registry first (`registry.json` → `shadcn build` → `public/r/`). Copy-paste view second. One variant: TS + Tailwind. |
| Legal | No official F1 font, no real driver/team names or liveries, no "F1" in the brand. MIT + Commons Clause. |
| Fonts | Components use `--font-display` and `--font-mono` only. Site defaults: Titillium Web + JetBrains Mono. Optional `registry:font` item. |
| Theme | `registry:theme` item `boxbox-theme`. Dark default, light supported. Semantic tokens for sectors, track status, tyres, flags. |
| Types | `registry:lib` item `boxbox-types` shared by all components via `registryDependencies`. |
| API | Data-driven root props + render slots + named exports of inner parts. Controlled/uncontrolled for stateful components. `className` + `data-slot` everywhere. |
| Repo | GitHub **private** until v1. Public at v1. |

## Phase 0 — Bootstrap (1 session)

**Goal:** empty app deploys to Vercel, CI green.

1. **Scaffold** TanStack Start with bun. Configure `tanstackStart({ spa: { enabled: true, prerender: { enabled: true } } })` and `nitro()` from `nitro/vite`. Confirm `bun run build` produces a static shell.
2. **Tailwind v4 + shadcn init** (`new-york`, CSS variables, base color neutral). Add `components.json` with `"registries": { "@boxbox": "https://react-boxbox.vercel.app/r/{name}.json" }` so the site can dogfood its own registry later.
3. **Tooling**: `.oxlintrc.json` (react, jsx-a11y, react-hooks native rules), `.oxfmtrc.json`, `vitest.config.ts` with jsdom + Testing Library, strict `tsconfig`. Scripts: `dev`, `build`, `typecheck`, `lint`, `format`, `format:check`, `test`, `registry:build`.
4. **GitHub**: `gh repo create react-boxbox --private`, push. `ci.yml`: bun install → typecheck → lint → format:check → test → build, on push and PR.
5. **Vercel**: link project, first deploy. (User runs `vercel login` if needed.)

**Done when:** `react-boxbox.vercel.app` serves a placeholder page and CI is green.

## Phase 1 — Foundation (1–2 sessions)

**Goal:** theme, types, fonts, and dataset exist and install from the registry.

6. **Types** (`registry/boxbox/lib/types.ts`): `Driver`, `Team`, `TyreCompound` (`S | M | H | I | W`), `SectorStatus` (`fastest | personal | slower | unset`), `TrackStatus` (`green | yellow | red | sc | vsc | chequered`), `TimingRow`, `GapMode`.
7. **Theme** (`boxbox-theme`): shadcn base tokens in OKLCH with `light` and `dark` maps, `--primary` as F1-style red, plus `--sector-*`, `--status-pit`, `--status-lapped`, `--tyre-*`, `--flag-*`, `--font-display`, `--font-mono`. Dark is the default on the site.
8. **Fonts**: site loads Titillium Web (700/900) and JetBrains Mono via `@fontsource`. Optional `registry:font` item points at Google Fonts. Components never import fonts.
9. **Registry pipeline**: `registry.json` with `boxbox-types`, `boxbox-theme`, `boxbox-font`. `bun run registry:build` → `public/r/`. **Verify** by running `bunx shadcn add @boxbox/boxbox-theme` into a scratch Vite app pointed at the local dev URL.
10. **Dataset + simulator** (`src/data/`): 20 fictional drivers, 10 fictional teams with colours, zod schema, `useRaceSimulation()` hook that mutates gaps, positions, sectors, tyres and pit status on an interval. Unit-tested.

**Done when:** theme installs into a scratch app and the simulator produces a stable 20-row grid.

## Phase 2 — Docs shell (1–2 sessions)

**Goal:** a component page template exists before the first component, so every component ships with its page.

11. **Layout**: header with brand + theme toggle + GitHub link, sidebar grouped by category (Timing, Broadcast, Race Control, Pit Lane), content area. Prerendered.
12. **Component page template** (`/components/$slug`): reads `src/content/<slug>/meta.ts`. Sections: live preview, **playground panel** generated from `controls.ts` (zod schema → boolean / number / select / color / text controls), props table (from the same schema), code tabs (source, `shadcn add @boxbox/<name>`, dependencies).
13. **Docs pages**: `/docs/installation` (registry namespace setup, theme install, fonts) and `/docs/theming` (token list, override examples).

**Done when:** a dummy component renders through the full template with working controls.

## Phase 3 — Components (1 session each, in this order)

Each step delivers: component + `registry.json` entry + `controls.ts` + `demo.tsx` + `meta.ts` + tests (pure logic + render smoke) + rebuilt `public/r/`. Simplest first, Timing Tower after its dependencies.

**Registry file conventions** (the shadcn CLI only rewrites imports that match `@/registry/<x>/{ui,lib,components,hooks}`):
- Component file: `registry/boxbox/ui/<name>.tsx`, item type `registry:ui`, `dependencies: ["motion"]`, `registryDependencies: ["@boxbox/boxbox-types", "@boxbox/boxbox-theme"]` (+ other `@boxbox/*` items it imports).
- Imports inside registry files: `@/registry/boxbox/lib/types`, `@/registry/boxbox/ui/<other>`, `@/lib/utils` for `cn`. Nothing from `src/`.
- `tsconfig` maps `@/registry/*` → `./registry/*` so the site resolves the same paths locally.

14. **Tyre Badge** — `compound`, `age`, `isNew`, `size`. Rotate on compound change. Exercises tyre tokens and the template.
15. **Sector Times** — `sectors[3]`, `lapTime`, `lapStatus`, `miniSectors`, `layout`. Fill + colour flash per sector, optional lap-time count-up. Exercises sector tokens.
16. **Driver Name Plate** — `driver`, `position`, `variant` (`compact | full`), `status`, `visible`, `align`. Wipe in/out with `AnimatePresence`, staggered children.
17. **Start Lights** — state machine `idle → arming → lit → out | aborted`. `autoStart`, `interval`, `holdRange`, `state`/`defaultState`, `onLight`, `onLightsOut`, `size`. No audio. Timer logic unit-tested with fake timers.
18. **Timing Tower** — `rows`, `mode` (`leader | interval | lapTime`), `maxRows`, `highlightTop`, `showTyre`, `showDrs`, `renderRow`. 2025-26 squared look. `layout` reorder, position flash, pit red, lapped blue, gap tick. Uses Tyre Badge. Sorting and gap-formatting unit-tested.
19. **Replay Bumper** — wraps `children`, fills its container. `label`, `play`/`onMidpoint`/`onComplete`, `duration`, `variant` (`wipe | slide | flash`), `color`.

**Done when:** six pages live, each installs from the deployed registry into a scratch app.

## Known issues

- **Vercel deep-link 404.** With SPA mode on Vercel, a route that was not prerendered returns Vercel's static 404 instead of `_shell.html` (open issue vercel/vercel#17627). Mitigation: every docs route is prerendered at build time via `crawlLinks`, so only unknown URLs 404. Revisit when the issue closes or when moving to SSR.
- **Vercel Git integration not connected.** `vercel git connect` fails from a git worktree and the Vercel GitHub App has no access to the private repo yet. Production deploys currently run from the CLI (`vercel deploy --prod`). Connect it from the Vercel dashboard (Project → Settings → Git) to get deploys on push.
- **Branch flow.** Work happens on `prowfish` (Orca worktree) and is pushed to both `prowfish` and `main` (`git push origin prowfish:main`). `main` is the GitHub default branch and the production branch.
